# Meta dashboard and runtime requirements for Edwyz WA

App: **Edwyz API**, App ID `1799953191201553`. Business portfolio `363324021484296`. Domain `wa.edwyz.com`. Embedded Signup configuration id `1456804329669326` (env `META_ES_CONFIG_ID`). Graph version pinned in code: `v26.0` (`GRAPH_API_VERSION`, `src/lib/config.ts`), used for every server call, the `FB.init` call and the Login for Business dialog URL.

Written 2026-10-27 by reading the code and the docs listed at the end; Instagram and Facebook Page ads added 2026-10-31 (section 1I, from `docs/IG-PAGE-ADS-SPEC.md` 8.1, 8.2 and 8.5). Nothing was checked in the live dashboard, so every "required value" is what the code needs, not what the dashboard currently shows. Dashboard menu names change; the paths below use the Login for Business / use-case layout and give the older name where it differs. Items Meta documentation could not confirm are marked VERIFY.

Why this exists: Facebook login failed with "JSSDK option is not toggled: please toggle the Log in with JavaScript SDK option to Yes". The class of problem is a Meta dashboard switch or list that the code silently depends on. Section 1 lists every such switch. Section 2 lists the same kind of dependency on our side (headers, CSP, cookies, env). Section 3 lists code changes found while checking.

## How the code uses Meta (what each flow depends on)

| Flow | Entry | Meta surface | Needs |
|---|---|---|---|
| WhatsApp Embedded Signup | `ConnectWhatsApp.tsx` -> `GET /api/onboarding/start` -> `FB.login` popup (JS SDK) -> `POST /api/onboarding/complete` -> `oauth/access_token` (no redirect_uri) | Login for Business, JS SDK, ES config `META_ES_CONFIG_ID` | JS SDK toggle, allowed domain, config, WhatsApp products |
| Facebook / Instagram / ads Connect | `ConnectionsPanel.tsx` and the readiness rows -> `useFacebookLoginPopup` opens a small window from the click, then `POST /api/meta-connect/start?popup=1` -> the window goes to `https://www.facebook.com/v26.0/dialog/oauth?config_id=META_LOGIN_CONFIG_ID&redirect_uri=https://wa.edwyz.com/api/meta-connect/callback` (state ends `.popup`) -> `GET /api/meta-connect/callback` -> code exchange with the same redirect_uri -> a small closing page that tells the opener the outcome (postMessage, BroadcastChannel `edwyz-meta-connect`, localStorage, meta tag). A blocked popup, or `META_LOGIN_POPUP=off`, falls back to the full-page redirect to the same callback, which ends on Connections | Login for Business web redirect, config `META_LOGIN_CONFIG_ID` ("Edwyz Connect Pages IG Ads") | Client OAuth, Web OAuth, strict-mode redirect URI list; `Cross-Origin-Opener-Policy` unset or `same-origin-allow-popups` on `/app/*` (C1) |
| WhatsApp webhooks | Meta -> `POST /webhooks/whatsapp` (HMAC with `META_APP_SECRET`, GET handshake with `META_VERIFY_TOKEN`) | WhatsApp > Configuration | callback URL, fields, per-WABA subscription |
| Lead webhooks | Meta -> `POST /webhooks/leads` (object `page`, field `leadgen`), then `GET {leadgen_id}` with the Page token | Webhooks product, Page object | callback, `leadgen`, per-Page subscription (code calls `POST {page}/subscribed_apps?subscribed_fields=leadgen`) |
| Data deletion | Meta -> `POST /api/meta/data-deletion` (signed_request) -> `{url, confirmation_code}`; status page `/data-deletion/status?code=` | App settings > Basic, Facebook Login settings | callback URL, no deauthorize route exists |
| Marketing API | `src/lib/ads/**` (the ads client behind the Spend Book) and `src/lib/promote/**` (posts, media, previews, forms, test leads, audiences, results by placement, review status) with the user token from Connect, Page edges with the Page token | Ads permissions, access tier | `ads_management`, `ads_read`, `pages_manage_ads`, `pages_read_engagement`, `instagram_basic`; Full access tier (section 1I) |
| Publishing | `src/lib/content/publishers.ts` Page `/feed`, `/photos`, `/videos`; Instagram `/media`, `/media_publish`, `content_publishing_limit` | Page and Instagram permissions | `pages_manage_posts`, `instagram_content_publish` |
| Conversions | `src/lib/conversions/worker.ts` `POST {dataset}/events` | Dataset (pixel) access | `ads_management`, dataset on the ad account |

## 3. CODE FIXES

Ordered by impact. Nothing here was applied; this auditor only writes this file.

1. **`src/lib/onboarding/index.ts` (high).** Reconnecting the same WhatsApp number does nothing: `runSteps` skips every step already `done` for `ref = wabaId:phoneNumberId`, including `exchange_code`, so the fresh code from `FB.login` is thrown away and an expired (60-day) or revoked token stays in place. Change: in `runSteps`, never skip `exchange_code` and `subscribe_app` (e.g. `const ALWAYS = new Set<StepName>(["exchange_code", "subscribe_app"]); if (!ALWAYS.has(step) && (await isDone(...))) continue;`), and update the "is idempotent: a second run does nothing" test in `tests/onboarding.test.ts` to expect a token exchange on every run. Resume after a failed run still works because each new attempt carries a new code.
2. **`src/components/connect/ConnectWhatsApp.tsx` (high).** `FB.login` runs after `await api("/api/onboarding/start")` and after the SDK download, so it can lose the browser's user-gesture allowance and be popup-blocked. Change: on mount, call `loadSdk(appId)` and fetch `/api/onboarding/start` into refs (re-fetch when the state is older than 8 minutes); in the click handler call `fb.login(...)` synchronously from the cached SDK and state; fall back to the current async path only when the cache is empty.
3. **`src/components/connect/ConnectWhatsApp.tsx` (medium, VERIFY first).** Add `sessionInfoVersion: "3"` to `extras` (`extras: { setup: {}, sessionInfoVersion: "3" }`) as in Meta's current Embedded Signup snippet, so `WA_EMBEDDED_SIGNUP` events include the waba/phone ids reliably. Test with a real signup before shipping.
4. **`src/lib/security/csp.ts` (medium, before `CSP_MODE=enforce`).** Add `https://www.facebook.com` and `https://web.facebook.com` to the `CONNECT` list (used by both `buildCsp` and `buildLegacyCsp`) so SDK requests are not blocked once the strict policy is enforced. Update `tests` that assert the exact policy.
5. **`docs/meta-checklist.md` (medium).** Step 3 lists only `https://wa.edwyz.com/oauth/callback`; add `https://wa.edwyz.com/api/meta-connect/callback` (the redirect that actually breaks under strict mode), change Allowed domains to `https://wa.edwyz.com`, add the second login configuration (`META_LOGIN_CONFIG_ID`, user access token, 13 scopes), add Webhooks > Page > `leadgen` to `https://wa.edwyz.com/webhooks/leads`, and add "Require App Secret = Off" and "IP allowlist empty or contains the VPS". Also reconcile `docs/app-review/00-overview.md` ("Phase A part 2 not built today") with `status.md` ("code present").
6. **`src/lib/graph/index.ts` (medium).** Add `appsecret_proof` to `graphFetch` and `graphFetchAs` (HMAC-SHA256 of the access token with `META_APP_SECRET`, hex, sent as query parameter `appsecret_proof`; skip it for the app token `id|secret` used by `debug_token`). Then turning "Require App Secret" on in the dashboard cannot take down every API call, and Meta's security recommendation is met. Until it ships, keep the dashboard setting Off (item 65).
7. **`src/lib/env-rules.mjs` line 102 (medium).** `checkSecret(env, "STATE_SECRET", 16, errors)` accepts 16 to 31 characters, but `src/lib/meta-connect/state.ts` throws 503 for under 32 in production. Raise the production minimum to 32 so `scripts/check-env.mjs` fails the deploy instead of the Connect button failing for users. Also add a warning when `META_LOGIN_CONFIG_ID` is unset in production (currently only an "OFF" line).
8. **`src/lib/conversions/worker.ts` (medium, VERIFY against the Conversions API for business messaging docs).** Pass `wabaId` into `buildConversionPayload` (resolve it from the conversation's phone number: `phoneNumber.waba.wabaId`) so `user_data.whatsapp_business_account_id` is sent with `action_source: "business_messaging"` events. Without it click-to-WhatsApp events are likely rejected with error 100.
9. **New `src/app/api/meta/deauthorize/route.ts` (low, optional).** Accept the signed_request (`parseSignedRequest` already exists), mark the matching `MetaConnection` rows (by `metaUserId = user_id`) `revoked` and clear tokens via the existing disconnect helpers, answer 200. Then set it as the Deauthorize callback URL (item 23). Until then leave that dashboard field empty.
10. **`src/app/api/onboarding/start/route.ts` and `complete/route.ts` (low).** Replace `createState`/`verifyState` with the tenant and user bound, single-use `issueState`/`consumeState` from `src/lib/meta-connect/state.ts` (or an equivalent with its own domain label), so a captured Embedded Signup state cannot be replayed within 10 minutes or across users.
11. **`src/lib/webhooks/processor.ts` `processAccountEvent` (low, privacy).** Store only an allow-listed subset of `change.value` (event name, waba_info ids, ban or violation fields) in `AuditLog.meta`, and ignore the coexistence fields (`smb_message_echoes`, `history`, `smb_app_state_sync`) instead of writing whole payloads, which hold customer message content. Alternatively keep those dashboard fields unsubscribed (item 39).
