# Edwyz WA security review, phase 3 (Meta connect, ads, leads, commerce, AI agent, MCP, compat API)

Scope: the code added in the phase 3 and growth wave, in the priority order given: `src/lib/meta-connect`, `src/lib/crypto`, `src/lib/graph`; `src/lib/ads`, `src/lib/optimizer`; the public surfaces (`webhooks/leads`, `webhooks/shopify`, `approve`, `api/approvals`, `api/creative/public`, `api/content/media-public`, `(site)/docs`); tenant isolation of new Prisma queries; SSRF and outbound calls; `src/lib/tenant-mcp`, `src/app/api/mcp`; `src/lib/ai-agent`; `src/lib/compat`, `src/app/api/ext`; personal data. Method: paper review of the working tree on 2026-10-27. Nothing was run, built or sent over the network. Line numbers refer to the files as read. Format and severity scale follow `docs/security-review.md`.

Items from the earlier review that are now closed and were re-checked in passing: nginx now overwrites `X-Forwarded-For` and `X-Real-IP` with `$remote_addr` (F3 part), `inbox/http.ts` now re-exports the strict `assertSameOrigin` (F14), `crypto/tokens.ts` now enforces a 16-byte tag and supports tenant-bound AAD (F20), `/api/internal/tick` and the data-deletion handler were not re-reviewed.

Totals: Critical 0, High 3, Medium 8, Low 15 (26 findings). Items marked UNVERIFIED could not be confirmed from the code alone.

## Answers to the specific questions in the brief

1. **Token handling and leaks (scope 1).** Tokens are sealed with `sealSecret(tenantId, ...)` (AES-256-GCM, AAD bound to the tenant, version 2) and opened only in `getAssetAccess`, `refreshConnection`, `disconnect`, the health worker, BYO MCP and Shopify secret lookup. I found no path that returns, logs or stores a token in plaintext: `listConnections`, `listAssets`, `getCampaign` and `adOptions` select no token fields; all `console.*` calls in the new code print fixed strings or `describeError` (class name and code only); `GraphError` messages never include the URL (the client_secret and `code` live in the query string only); Meta error messages shown to users go through `sanitizeMessage`; test files contain no token-looking literals. `graphFetchAs` sets the token in an `Authorization` header only. Page tokens are stored per asset and nulled on disconnect.
2. **OAuth state binding.** `issueState` signs `nonce.timestamp` with a key derived by HMAC from `STATE_SECRET`, tenant id and user id, stores the nonce, and `consumeState` verifies against the CURRENT session's derived key, enforces 10-minute age, and deletes the nonce in one `deleteMany` (single use). An attacker's state does not verify under a victim's session (no login CSRF), the callback requires an admin session, `tenantId` is never read from the URL. Sound.
3. **Money paths.** The only code that sets anything ACTIVE is `activateCampaign` (admin, `confirm: true`, exact `confirmedTotalMinor`, cap, client approval if any exist). Launch and drafts are PAUSED (`status: "PAUSED"` hard-coded in every builder). The optimizer worker (`engine.ts`) only creates proposals. Applying a proposal requires admin plus `confirm: true`. Shift is zero-sum, at most 20 percent (`Math.min(cfg.maxShiftPct, 20)`), checked again against live DB budgets, and `setAdSetBudget` re-clamps to the cap. There is no route that raises a budget without an authenticated admin. The gap is the cap definition (P3-01) and workspace state (P3-05).
4. **Tenant isolation.** I scripted a scan of every `prisma.<model>.<op>(` in the new directories for a `tenantId` within the call; it flagged 22 call sites and I read each. All are safe: they use a `where`/`base`/`scope` variable that includes `tenantId`, or are intentional system scans (`runDueSequences`, `expireOldCarts`, `checkTokenHealth`, `runAllTenants`) followed by tenant-scoped work, or update by id after a tenant-scoped read in the same function (`conversions/worker.ts:14,18,75`, `content/publish.ts:89,93` already pair the id with `tenantId`). Defence-in-depth gaps (update by `id` only after a scoped read): `conversions/worker.ts:14,18,75`, `leads/runner.ts:44-52` (`processRun` claims by `id` only; tenant comes from the row), `ads` `launchCampaign` reads by id with tenant. Cross-tenant references are validated: `adAccountAssetId`, page, instagram and WhatsApp number (`ads/service.ts:118-129`), `creativeAssetId` (`resolveCreative`), `datasetAssetId` (resolved through `listAssets(tenantId)`), post `assetIds` (`content/service.ts:68-73`), lead sequence `templateId` and `chatbotId` (`leads/service.ts:185-186`), commerce `templateId` and `phoneNumberId`, AI `phoneNumberId`, approvals via `HANDLERS[...].owner(tenantId, id)`. ids in URLs are always combined with `actor.tenantId`.
5. **SSRF.** BYO MCP and AI page fetch: `assertPublicUrl` (https only, ports 443/8443, no credentials, blocked names, IPv4/IPv6/mapped/NAT64/6to4 ranges, every resolved address checked), connection pinned to the validated address, no redirects (MCP) or per-hop re-validation (page fetch), byte and time limits. Only `creative/site.ts` lacks pinning (P3-09). Commerce makes no outbound calls.

## Prioritised fix list

1. P3-01: sum the cap across all active campaigns (money).
2. P3-02 and P3-07: stop `getActor` honouring API keys; tie keys to a live membership.
3. P3-03: no risky or unvalidated BYO tools in the customer-facing AI agent.
4. P3-05: suspension, deletion and lock must pause ads, revoke tokens and stop workers.
5. P3-06: opt-in and template approval in `sendMessageV1`.
6. P3-04: confirm token and send caps for MCP sends.

## Checked and found fine

- Webhook signatures: `webhooks/leads` and `webhooks/shopify` verify HMAC-SHA256 over the exact raw text body before parsing, compare in constant time (`safeEqual`, `timingSafeEqual` with a length check), enforce body limits while streaming (1 MB, 512 KB), return 5xx on enqueue failure so Meta/Shopify retry, and keep only ids from the lead payload (PII is fetched later with the page token). Shopify lookup is by `shopDomain` regex (`*.myshopify.com`) and the per-store secret, so a signature for one tenant's secret cannot write another tenant's carts.
- Approval links: 256-bit random token, only the SHA-256 hash stored, unknown/expired/decided/bad-nonce all collapse to the same response, single-use decision via an atomic `updateMany`, per-IP and per-token limiters, nonce HMAC bound to the token hash with constant-time compare, no open redirect (the redirect is a fixed path with `encodeURIComponent(token)`), `Referrer-Policy: no-referrer`, comments cleaned of control and bidi characters and rendered through React text nodes. `resend` checks opt-in, opt-out, 24-hour window and approved template before rotating the link.
- Signed media URLs: HMAC over tenant, file and expiry, ids and file keys match strict regexes (no path traversal: `resolveSafe`/`resolveMediaPath` re-check the directory), 1-hour TTL for content media, magic-byte check on upload, `nosniff`, CSP `sandbox` on creative files, constant-time compare.
- `(site)/docs/**` is static content built from `ENDPOINTS` and `API_SCOPES`; no user input, no `dangerouslySetInnerHTML`.
- Compat API: every endpoint resolves its scope from the single spec table (`runtime.ts`), authenticates keys only (cookies ignored), rate limits per key, checks the paywall on writes, limits bodies to 64 KB, caps `page_size` at 100, and always filters by `actor.tenantId`; webhooks created through it go through the existing SSRF validation.
- Tenant MCP: scope per tool is enforced both on `tools/list` and `tools/call`; schema validation with `additionalProperties: false`; broadcasts can only be saved as drafts; marketing templates check opt-in in the tool itself; notifications without id are ignored; errors never echo internals; bodies capped at 32 KB, results at 24 KB.
- Hashing for conversions: SHA-256 of trimmed lower-case email and digits-only phone, deterministic `event_id` for dedupe, skipped for opted-out contacts, no raw identifiers stored or logged.
- Graph client: POSTs are never retried on ambiguous failures (`guardAllPosts`), so ads, posts and events are not created twice by retries; the base URL is fixed to `graph.facebook.com`.
- OAuth callback, `start`, `disconnect`, `refresh`: admin role, strict `assertSameOrigin` on POSTs, `connectionId` validated by regex and always looked up with `tenantId`.
- CSV export of leads neutralises formula cells and requires admin.
- Outbound LLM calls: key in a header only, prompt size capped, no phone numbers, tenant ids or other tenants' data in prompts; STOP messages and opted-out contacts are excluded from the AI agent; replies respect the 24-hour window through `sendText`.
